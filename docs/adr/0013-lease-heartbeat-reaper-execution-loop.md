# Claim-then-execute via a lease + heartbeat + reaper; the lease lives on the Attempt

A Worker cannot hold the `SELECT … FOR UPDATE SKIP LOCKED` row lock for the duration of a Run's execution — that would pin a connection and turn a long job into a long-open transaction (bloat, connection exhaustion). So the claim is a **short transaction** (insert an Attempt, flip the Run `→ running`, commit, release the lock) and execution happens *outside* it. To make that safe we use a **lease**: the claiming transaction stamps the new Attempt with `claimed_by`, `started_at`, and `lease_expires_at`; the executing Worker **heartbeats** (renews `lease_expires_at`) while the Attempt is in flight. The **Reaper** — a pass of the Scheduler's existing reconciliation sweep (ADR-0007) — finds **open Attempts** (`ended_at IS NULL`) whose lease has expired, closes each (`ended_at = now()`, `error = 'abandoned'`), and returns the parent Run to a claimable state. This turns "Worker died mid-run" from a silent permanent hang — the exact crontab-blindness Thrum sells against — into an observable, recoverable state.

## Considered options

- **Hold `FOR UPDATE` for the whole execution** — rejected: a connection pinned per in-flight Run, and a 10-minute job becomes a 10-minute open transaction. Non-viable at any concurrency.
- **Lease columns on the Run vs. on the Attempt** — chose the **Attempt**. A lease is a property of one execution try, and a try *is* an Attempt (ADR-0002). An orphan reduces to a clean predicate (`ended_at IS NULL AND lease_expires_at < now()`), no per-try lease state is duplicated onto the logical Run row, and "how long did attempt 2 hold its lease" stays answerable.
- **A separate reaper process** — rejected for v1: orphan-detection and missed-detection are the same query family ("Runs/Attempts in the wrong state for the current clock"), so reaping folds into the sweep that already runs. The `--scheduler-only` seam (ADR-0007) carries the reaper out if isolation is ever wanted.

## Heartbeat mechanism

Under the one-event-loop execution model (ADR-0005), the heartbeat is a **single per-Worker renewal coroutine**, not one per in-flight Run: each tick it bumps `lease_expires_at = now() + lease_ttl` for *all* of that Worker's open Attempts (`claimed_by = self.id AND ended_at IS NULL`) in one short transaction on a **dedicated connection** (separate from both execution sessions and the Scheduler's advisory-lock connection). It renews at `interval = lease_ttl / 3` (default 15s renew / 45s TTL), so two consecutive missed renewals are required before a live Run looks orphaned — slack against a momentarily busy loop without slowing real-orphan detection at the cron timescale. **Known limitation:** a sync/CPU-bound Task that blocks the event loop can starve the heartbeat and get itself falsely reaped → double execution; this is accepted because at-least-once (ADR-0014) is the correctness backstop and blocking Tasks belong on the thread/process-pool path (ADR-0005), a later slice. The heartbeat runs on *every* Worker; only the *sweep* (reaper + missed + materialize) is gated behind the leader's advisory lock.

## Consequences

- **The Run loops, Attempts accrue.** The Run cycles `scheduled`/`pending → running → pending → running …` while immutable Attempt rows accumulate, until success (`succeeded`) or budget exhaustion (`failed`). Retry backoff is a `next_attempt_at` timestamp on the Run gating the claim — mirroring `fire_time` for `scheduled` Runs, so one dispatch predicate (`pending AND next_attempt_at <= now()`) OR (`scheduled AND fire_time <= now()`) covers both.
- **Leader death is self-healing via the same mechanism.** If the elected leader dies mid-run, it stops renewing its advisory lock; another Worker wins the lock, becomes Scheduler, and its next sweep reaps the dead leader's orphaned Attempts. Who reaps the reaper: the next reaper.
- **Two new tunables:** lease TTL and heartbeat interval. Orphan-detection latency ≈ sweep interval + residual lease — irrelevant at the cron wedge's timescale.
- **Late/Overrun are derived flags, not lifecycle states** (orthogonal axes to status); `missed` *is* a terminal state.
